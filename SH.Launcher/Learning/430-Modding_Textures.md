# XML Modding: Textures

To add a new textures to the game, you need a simple XML mod

Here we use the following technical terms:
- **Sprite**: a small image, usually with some transparency, used to decorate a part of an object at a given viewing angle
- **Sprite Sheet**: a large image, which stores several **Sprite** images inside it - it's like a big pack of minor images
- **SpriteAtlas**: a whole set of **Sprite Sheets** - from the game's original **Sprite Sheets**, or from a given mod
- **Animation**: a construct which joins one or more **Sprites** by attaching them to a **Bone Skeleton** for one or more frames

# Quick Summary: How to add Textures ?

In the mod:
- Mod has **Sprite** textures stored as individual **textures**/**\*.png** files
- Mod defines **library**/**animations_\*.xml** file(s)

**JAVA mods**:
- a **JAVA mod** can simply locate mod files through the **mods.json** file generated by **Space Haven Launcher**

**How to reference new Sprite images**:
- **assePos** in **library**/**animations_\*.xml** use the **filename** attribute to reference a specific **Sprite**, e.g. **filename="MyNewTexture001.png"**

**ATTENTION**:
- Do **NOT** use **library**/**textures\*.xml** files in the mod, it is a modding design error
- If you need to replace images, do it by replacing the animations instead
- Just use **library**/**animations\*.xml** or **patch**/**animations\*.xml** for this purpose

**DEPRECATED FILES**:
- Do **NOT** provide any **library**/**generated_textures.xml** file in your mod
- Do **NOT** provide any **custom_texture_\*.png** file in your mod
- These are just deprecated intermediate files generated by the old **Mod Loader** tool

**What Space Haven Launcher does instead ?**
- it does NOT require any such files
- it does NOT generate any files in mod directories
- it generates all intermediate files in its own **build** directory

# NEAREST vs. LINEAR texture filtering

In order to apply one or another, Space Haven Launcher supports:
- Attribute **filter** in **assetPos** entries referencing a sprite texture via **filename**
- This attribute can be set to: "Nearest" or "Linear" (case insensitive)
- Or to their respective numeric values: "0" or "1"
- When not set, Space haven Launcher defaults to "Nearest" filter

How to use these filters?
- If you need a sprite texture to have sharp and pixelated art style, e.g. for a new facility, use "Nearest"
- If you need a smooth but slighly blurred texture, e.g. for a turret shot or for a background image, use "Linear"
- Just try it and compare the results

# How does Space Haven Launcher merge textures ?

**Space Haven Launcher** makes ALL **Sprites** (*.png files) available in one or more new **Sprite Sheets** (CIM files)

First it creates **Sprite Sheets**:
- the **Sprite** images (**textures**/**\*.png**) are added in an optimal way to the **Sprite Sheet** (CIM file), like in Tetris
- the size of the CIM file image is then optimally calculated
- the size of the CIM file image can be configured to always be 2048 x 2048 in the [System Core](tab://SystemCore) tab
- each **Sprite Sheet** gets a new ID, also used as filename for the CIM file, considering all enabled mods

Then **Sprite Sheet** and **Sprite** metadata is processed:
- new entries are written to Space Haven's **textures** file for new **Sprite Sheets** and new individual **Sprites**
- the **assetPos** entries in the mod's **library/animations\*.xml** files containing "filename" references are remapped to "a" references
- the "a" references of **assetPos** entries point to the "n" attribute of each new **Sprite** (region)


**That's all !**
