# XML Modding: Textures

To add a new textures to the game, you need a simple XML mod

Here we use the following terms already explained in previous learning entries:
- **Sprite**: a small image, usually with transparency, used to decorate a part of a game object
- **Sprite Sheet**: a large image, containing several **Sprite** images in it
- **SpriteAtlas**: it's a set with one or more **Sprite Sheets**
- **Animation**: this joins **Sprites** by attaching them to **Bones**, and shows them in one or more frames

# Quick Summary: How to add Textures ?

In the mod:
- Mod has **Sprite** textures stored as individual **textures**/**\*.png** files
- Mod defines new **library**/**animations_\*.xml** file(s)
- Mod patches with **library**/**animations_\*.xml** file(s)
- No **textures** XML file should be provided, this is generated automatically!

**JAVA mods**:
- a **JAVA mod** can simply locate mod files through the **mods.json** file generated by **Space Haven Launcher**

**How to reference new Sprite images**:
- **assePos** nodes in **library**/**animations_\*.xml** have **filename** attribute referencing a specific **Sprite** image
- a patch operation in **patch**/**animations_\*.xml** changes the **filename** attribute
- when a mod touches an **assetPos filename** reference, it becomes the owner of that reference
- the mod owning a texture reference must provide it's image
```
<assetPos ... filename="MyNewTexture001.png" />
```

**DESIGN**:
- Do **NOT** use **library**/**textures\*.xml** files in the mod
- If you need to replace images, do it by replacing the animation references instead
- Use **library**/**animations\*.xml** or **patch**/**animations\*.xml** for this purpose

**DEPRECATED FILES**:
- Do **NOT** provide any **library**/**generated_textures.xml** file in your mod
- Do **NOT** provide any **custom_texture_\*.png** file in your mod
- These are deprecated intermediate files generated by the old **Mod Loader**

**What Space Haven Launcher does instead ?**
- it does NOT require any such files
- it does NOT generate any files in mod directories
- it generates all intermediate files in its own **build** directory

# NEAREST vs. LINEAR texture filtering

In order to apply one or another, Space Haven Launcher supports:
- Attribute **filter** in **assetPos** entries referencing a sprite texture via **filename**
- This attribute can be set to: "Nearest" or "Linear" (case insensitive)
- Or to their respective numeric values: "0" or "1"
- When not set, Space haven Launcher defaults to "Nearest" filter

How to use these filters?
- If you need a sprite texture to have sharp and pixelated art style, e.g. for a new facility, use "Nearest"
- If you need a smooth but slighly blurred texture, e.g. for a turret shot or for a background image, use "Linear"
- Just try it and compare the results

# How does Space Haven Launcher generates textures ?

After merging and patching the animations XML files, the **Sprite Sheets** are generated:
- The last mod which changes the attribute **filename** of an **assetPos** entry is now its owner!
- The mod owning the reference must provide the **Sprite** image
- 2 **Sprite Atlases** are created: one for **nearest** texture filtering, and one for **linear** texture filtering
- the **Sprites** are packed into **Sprite Sheets** with size 2048 x 2048 pixels
- the **Sprite Sheets** contain **Sprite** images of all mods, all mixed together!
- There are **Sprite Sheets** for **nearest** texture filtering and others for **linear** texture filtering

**That's all !**
